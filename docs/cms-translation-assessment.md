## 候选路线

| | Payload + Next.js | Strapi + Next.js |
| --- | --- | --- |
| 形态 | 后台与现有 Next.js 项目集成，可同一代码库部署 | Strapi 内容服务独立部署，Next.js 通过 API 获取 |
| 适合 | 一个团队共同维护网站和内容后台，代码集中 | 希望内容服务独立，未来多个前端复用 |
| 多语言 | 原生字段级本地化；需自行设计 13 种语言、缺译和翻译工作流 | 国际化是免费功能，按内容类型和字段开启；自动 AI 翻译属于付费功能，不能默认包含 |
| 媒体与数据库 | 支持上传；支持 PostgreSQL、SQLite、MongoDB 等官方适配器 | 支持媒体库；支持 PostgreSQL、MySQL、MariaDB、SQLite |
| 代价与风险 | 与 Next.js 版本和运行时耦合；当前官方安装要求 Node `^22.23.4 || >=24.22.1`，现有本机 22.19.0 不满足，需要隔离升级验证 | 多一套服务、API 鉴权与部署；免费与付费功能边界需要按实际版本核对 |

初步倾向 Payload + PostgreSQL：项目目前以 Next.js 为主，编辑团队和部署预期相对集中，后续关联产品、栏目和多语言字段的代码可统一维护；但这只是基于需求的判断，不是已完成验证。Strapi 是合理备选，尤其适合未来有多个不同前端或希望单独运维后台的情况。PostgreSQL 是关系型数据的候选，并非用户已确定的数据库。

对比验证应在不覆盖当前原型的隔离目录进行：分别建立产品、翻译、媒体的最小模型；验证 13 语言配置、缺译、编辑后前台刷新、关联、图片、权限、运行环境和备份恢复的基础流程；记录实际版本和限制。生产环境的完整安全及部署验收另做。验收后再确认最终方案。

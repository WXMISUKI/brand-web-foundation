在新工作区采用 JCodesMore 的 Next.js 16 / React 模板和流程，使用项目隔离的 Node 24；先用结构化本地示例数据与语言路由，业主确认更新流程后再接 CMS。优势是接近候选工具的预期工作环境；代价是引入其完整依赖、需要解决 Node 版本和评估依赖维护。工具工作流仍需要人工观察、开发和对照，不能保证复刻质量。

## B：自主建立轻量 Next.js 项目

采用 Next.js / React，自行建立适合产品内容与多语言的结构，借鉴复刻工具的页面采集和逐段对照方法；先本地数据，后续再决定 CMS。优势是依赖和项目结构更可控；代价是需自行处理模板提供的配置与组件，可能增加初始工作量。

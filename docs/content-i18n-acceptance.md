# 内容及多语言验收草案

状态：待业主和技术方案确认；这里描述验收目标，不表示能力已实现。

2026-11-05 用户确认各语言采用独立 URL，先用中文和英文示例验证切换、直接访问和刷新；正式语言集合仍需业主确认。

当前原型的中文首页为 `/`，英文首页为 `/en`；首页、产品列表与详情、示例方案、企业介绍及联系页均有对应的中英文路由。产品列表切换保留 category 和已提交的搜索词，详情保留 slug；搜索词不会自动翻译。英文样例 B 故意缺译并显示 Translation pending，这仅是原型策略。首页轮播和兴趣分类组件由两种语言共用，作物及种植方式入口连接示例方案，图片和译文均为示例。

中文根布局输出 `html lang=zh-CN`，英文输出 `html lang=en`，并配置示例标题和描述及 noindex。曾浏览器验证筛选页切换、刷新及根语言；未覆盖全站。跨根布局切换会触发完整页面导航。正式缺译策略、域名、hreflang、规范网址、真实译文和收录策略尚未确定；不能将原型验证视为 SEO 验收。官方参考：https://nextjs.org/docs/app/guides/internationalization

## 内容模型候选

| 对象 | 候选字段 | 说明 |
| --- | --- | --- |
| 产品 | 稳定标识、分类、图片、规格、参数、应用场景、发布状态、排序 | 参数保留原始单位与来源；不推算未确认数值 |
| 产品翻译 | 所属产品、语言、名称、简介、使用说明、SEO 文案 | 不同语言版本独立标记审核状态 |
| 分类 | 稳定标识、排序、各语言名称和介绍 | 分类规则由业主确认 |
| 媒体 | 文件、替代文字、来源、授权状态 | 正式站仅使用获授权素材 |

这些是设计候选而非数据库方案。链接标识、内容版本、发布审核及后台权限须随实际维护方式确定。

## 原型验证场景

1. 使用至少两类、三条明确标注为示例的产品；验证列表、分类筛选、详情以及不存在产品的处理。
2. 使用两套明确标注为测试的界面文案和产品译文；从列表及详情切换语言，检查显示、刷新及直接访问。
3. 构造一条缺译示例；按经确认的缺译规则显示，不能悄悄展示为已审核的翻译。
4. 检查缺失图片或可选字段时的展示，窄屏和桌面上没有遮挡主要操作。

## 正式内容验收

- 业主确认产品清单、规格、单位、成分和使用说明的准确性与有效日期；提供各语言审核人。
- 真实媒体及下载资料记录来源与使用授权；替换全部仅供研究的参考站素材及示例数据。
- 确定维护人如何新增、编辑、审核、发布、撤回与更正；依据所选方案实际走完流程。
- 确定语言集合、默认语言、URL、未翻译页面处理及搜索引擎配置；每种上线语言抽查完整访问链路。
- 表单仅在接收方、用途及失败处理确定后接入；实际验证接收与错误反馈。

当前未知：目标语言、译文提供方、内容数量和更新频率、编辑人数与后台、产品数据来源、询盘收件渠道。无真实资料时只能完成示例验证。

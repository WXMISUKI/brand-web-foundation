# 独立系列页与种植方式索引设计

日期：2026-11-09  
状态：**待用户确认后实现**  
阶段：P3-B 参考结构收口

## 意图

Haifa 参考站具有独立的产品系列入口和种植方式入口。当前 KOMU 站分别使用产品分类筛选和首页兴趣区承接，主链路可用，但页面层级仍被审计标为 `GAP/PARTIAL`。本设计补齐结构层级，同时保持当前产品审核、询盘关闭和 noindex 保护状态。

## 目标

- 增加公开英文/中文的产品系列入口页，能从目录和导航到达。
- 增加公开英文/中文的种植方式索引页，能从导航和首页兴趣区到达。
- 复用现有 Payload 产品、分类和 `solutions` 数据，不新增数据库集合或迁移。
- 保持产品 `owner-review`、`claimsVerified=false`、询盘 disabled、noindex 和未完成语言预览边界。
- 让页面在 320/390/768/1280/1440 视口下通过根溢出、遮挡、键盘和语言 counterpart 验收。

## 非目标

- 不复制 Haifa 品牌、配方、认证、施用量、案例结果或下载资料。
- 不凭空生成产品推荐、施肥剂量、生长阶段或作物适用性。
- 不新增 `ProductSeries`、`GrowingMethods` Payload collection，不改变生产数据库结构。
- 不启用询盘，不解除 noindex，不扩大生产语言范围。

## 方案比较

### 方案 A：轻量独立路由（推荐）

- 系列页使用现有分类和产品查询结果，路由建议为 `/{locale}/products/series/{slug}`。
- 种植方式索引建议为 `/{locale}/solutions`，详情继续使用 `/{locale}/solutions/{slug}`。
- 页面适配层只组合现有目录卡、方案卡、来源提示和联系入口。
- 优点：没有迁移和后台模型风险，能快速消除结构 GAP；缺点：系列级长文案、媒体和下载仍不能由后台独立维护。

### 方案 B：完整内容模型

- 新增 `ProductSeries` 与 `GrowingMethods` Payload collection，含多语言、媒体、富文本、关联产品和后台维护。
- 优点：最接近参考站的长期内容能力；缺点：需要 schema、迁移、后台回读、备份恢复和多语言数据验收，当前资料不足时容易产生更多占位内容。

### 方案 C：保持现状

- 继续使用分类筛选和首页兴趣区，不增加独立页面。
- 优点：无开发风险；缺点：继续保留参考结构 GAP，不满足完整复刻目标。

本设计提出采用方案 A，因为当前首要缺口是可到达的页面层级，不是新的事实数据模型。若用户选择方案 B，本设计作废并重新进入完整架构设计门禁。

## 页面行为

### 产品系列

- 系列索引只列出当前已有产品分类；每个系列显示产品数量、已接入产品卡和“资料仍需逐条审核”的统一提示。
- 系列详情只引用现有产品简介、页码、规格表和来源预览，不生成系列 claims、剂量、证书或下载。
- 分类筛选与系列页保持 URL counterpart；无效系列 slug 返回 404。

### 种植方式

- 索引按现有 `solutions` 中 `group=method` 的条目生成卡片。
- 详情继续使用现有方案组件；没有业主确认的作物关系、剂量和推荐时只显示结构说明与联系入口。
- 索引和详情都明确哪些内容是示例/待确认，不把示例图片或通用文案写成真实案例。

## 验收门禁

1. `typecheck`、内容校验、locale/RTL 合同通过。
2. 英文/中文索引、详情、counterpart、canonical、noindex 和未开放语言边界通过 HTTP 合同。
3. 生产真实浏览器验证 390/1280：导航到达、键盘 Enter/Escape、焦点返回、卡片点击、无根溢出和无固定栏遮挡。
4. 生产 smoke、SEO、`/api/ready` 通过；数据库和媒体计数不变。
5. P3-B 只在上述证据全部通过后标记 PASS-SCOPED；失败则回到本阶段修复，不推进询盘或 noindex 决策。

## 待确认事项

- 若采用方案 A，是否接受系列详情只由现有产品分类数据组成，不提供独立系列级富文本和下载管理。
